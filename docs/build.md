# Build and identity

Install Python 3.11 or later, GNU Make, and Retrolarium Kit. The exact external
dependency commits, compiler sources and binary hashes are pinned in
`config/toolchain.json`. The build verifies the compiler binaries before use;
Kit supplies AS and an authentic p2bin supporting both Z80 compression modes.

Import the five user-owned images with `make init ROM_ROOT="path/to/dumps"`.
Their original filenames, canonical local paths, sizes and cryptographic hashes
have one owner, `assets/manifest.json`. No input image is distributed here. Then
run `make split`, `make check-assets`, and `make verify-all`.

`make` shows help. `make verify PROFILE=s3-us` checks one profile. Other
accepted IDs are `s3-eu`, `s3-jp`, `sk` and `s3k`.
`config/revision_profiles.json` owns the entry, defines and composition order,
rather than separate build scripts.

The regional Sonic 3 images differ only at header offset 0x1f0. The assembler
receives the region character as a define; no opaque revision patch is applied.
Sonic 3 and Sonic & Knuckles remain two different sibling engines. S3&K is the
exact 4 MiB concatenation of the two verified base images, in S&K/S3 order.

Each non-composite image is assembled with AS, then linked through p2bin with
the original segment modes and padding. Both Z80 drivers remain executable
assembly source. p2bin reproduces their original uncompressed (S3) or authentic
Kosinski (S&K) segments. Python updates the cartridge end address and checksum.
Preservation verifies sizes, every byte, SHA-1 and SHA-256 against user input.

Sample rate and length declarations are source metadata under
`Sound/*/metadata`. Raw PCM/DPCM samples are extracted from ROM, not regenerated
from WAV. The source includes only files below the single ignored `data/` root.
Everything generated by assembly, linking and verification goes below ignored
`build/`. `make clean` removes disposable images/objects/relocation work only;
it never deletes original inputs, extracted assets or the reconnaissance
evidence.

`make test` runs without ROM files; its optional private-input case explicitly
skips when they are absent. `make audit-private` checks every historical path of
all reachable Git blobs and the current index against asset hashes, binary
suffixes, private root paths and an explicit binary allowlist. The allowlist is
currently empty. A passing build is not a release: symbolic pointer, runtime,
documentation and 2.0 content gates must also pass.

AS source uses `.s`; sample declarations use `.inc`. Retrolarium Kit's AS style
scanner recognizes these suffixes. Entry and include paths are renamed
mechanically; the source instruction/data order is unchanged.

`make lint` checks every AS source and the tracked text, Python, JSON and
Markdown without changing source files. `make format` applies the same style and
finishes with lint. Label-field declarations have explicit colons, and
assignments use `equ`/`set`, so canonical indentation preserves their AS
meaning. Comment banners use ASCII and avoid looking like macro definitions.

The Makefile serializes its targets, including when a caller has parallel make
flags. All emulator launches additionally wait for any already running MAME. Run
`make check-lockon check-numeric-operands` after verifying assembly, and read
[verification limits](verification.md) before interpreting a passing check as a
release result.

Music and SFX are ROM-extracted SMPS3/SMPS4 streams under `data/Sound/SMPS/`.
The audio catalog owns ABI applicability, while the asset manifest owns storage
identity. `make check-audio-storage` is ROM-less; `make check-audio-binding`
compares storage symbols and dialects with a verified AS build. Generic FM
helpers required by the executable drivers retain their permission notice; no
score assembly or full score macro library remains in the final tree.
